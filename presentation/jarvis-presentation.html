Deep Dive LangGraph — The Orchestration Engine

What is LangGraph?

LangGraph is a traffic controller for AI agents. It decides which specialist agent to call, in what order, and handles the results. Think of it as a manager who assigns the right task to the right team member.

OPEN SOURCE MIT LICENSE FREE

Install via pip. Self-hosted. No vendor lock-in.

github.com/langchain-ai/langgraph

Used in production by

Klarna, Replit, Elastic, LinkedIn

Why we chose it

Graph-based workflows with checkpointing (can pause and resume), human-in-the-loop (ask user before acting), and parallel execution (run 2 agents at once).

How LangGraph Routes a Voice Request
User says:
"Am I free Thursday?"
▼
Supervisor Node Understands intent, picks the right agent Intent: calendar_query
▼ routes to the right specialist
Calendar Agent ✓ SELECTED Checks free/busy via Graph API
Scheduler Agent Creates meetings
Research Agent Web search
Briefing Agent Pre-meeting prep
▼ agent returns result
Result: "Thursday is free from 2–5 PM" Supervisor composes spoken answer
▼
Voice: "Yes, you're free Thursday afternoon from 2 to 5."
Key idea: LangGraph is the brain's routing system. It never answers questions itself — it sends each question to the specialist who can answer it best, then assembles the response.
Deep Dive Skills — The AI's Living Knowledge

What are Skills?

Skills are written instruction files that tell each agent exactly how to do its job. Think of them as an employee handbook for AI — not code, but clear step-by-step procedures.

Why not just hardcode the logic?

Skills are editable without redeploying code. If the user wants briefings to include competitor news, we update a markdown file — not the application.

Filled in real-time

Skills grow smarter over time. As the user interacts with Jarvis, preferences are learned and skills are refined. Week 1: generic. Week 4: personalized. Week 12: deeply tuned.

Versioned & tested

Every skill change is tracked in git. An evaluation suite runs before any skill update goes live. A human approves.

Example: daily-briefing Skill File
# skills/daily-briefing/SKILL.md Name: Daily Briefing Agent: Briefing Agent Trigger: Every day at 06:00 OR "brief me on my day" Steps: 1. Fetch today's calendar events 2. Rank by importance (VIP attendees first) 3. For each meeting, pull: - Last interaction with attendees - Open action items - Unresolved debates 4. Check top-ranked Teams messages (triage score > 7) 5. Check pending follow-ups that are overdue 6. Compose spoken brief: 60-90 seconds max Tone: Concise, professional, no filler words Privacy: Never mention private-scope data in shared context

Deep Dive Microsoft Graph — Connecting to M365

What is Microsoft Graph?

Microsoft Graph is the official API to access Office 365 data — Calendar, Teams, Mail, People, SharePoint. It's the secure doorway into the user's work data.

Admin Consent Required

An Entra ID admin must approve each permission before Jarvis can access any data. This is a one-time setup. Without it, every API call returns 403 Forbidden.

Setup steps

1. Register an app in Entra ID
2. Request specific permissions
3. Admin clicks "Grant consent"
4. Enable transcript access in Teams admin
5. Jarvis gets OAuth tokens to call the API

Permissions Jarvis Needs
PermissionTypeWhat it accesses
Calendars.ReadWriteDelegatedRead/write the user's calendar events
User.ReadBasic.AllDelegatedLook up people by name
People.ReadDelegatedResolve "Bharath" to a contact
Chat.ReadDelegatedRead Teams chat messages (triage)
Mail.ReadDelegatedRead Outlook emails (triage)
OnlineMeetingTranscript.Read.AllApplicationFetch Teams meeting transcripts
Common Errors to Watch For
401
Token expired. Refresh the OAuth token. Tokens last 1 hour.
403
Permission missing. Admin hasn't granted consent for this scope.
429
Throttled. Too many requests. Back off and retry with exponential delay.
503
Service unavailable. Graph is temporarily down. Queue and retry.
Auth Hierarchy — Who Sets Up What?
Mercedes-Benz M365 Tenant (your organization) └── App Registration: "Jarvis CEO" (one-time setup by IT admin) ├── Client ID + Secret (stored in AWS Secrets Manager) ├── Permissions granted (admin clicks "Grant consent" — once) ├── Teams Admin enables transcription (once) └── Users (each signs in with their own M365 account): ├── Bharath → his token → GET /me = Bharath's calendar, Teams, mail ├── Anupama → her token → GET /me = Anupama's calendar, Teams, mail └── Manager X → their token → GET /me = their data only No Teams IDs needed. No Channel IDs. No per-user provisioning. The /me endpoint auto-resolves to whoever's OAuth token is used.
Example API Call
// Get Bharath's next meeting — just use /me with his token GET https://graph.microsoft.com/v1.0/me/calendar/events ?$filter=start/dateTime ge '2026-10-09T00:00:00' &$orderby=start/dateTime &$top=1 Authorization: Bearer eyJ0eXAi...bharath_token // Response: { "subject": "Project Delta Sync", "start": { "dateTime": "2026-10-09T15:00:00" }, "attendees": ["bharath@mercedes.com", "anupama@mercedes.com"] }
Key idea: Microsoft Graph is the single secure gateway to all M365 data. Every permission is explicit, admin-approved, and audited. No back doors.
Deep Dive Second Brain — Cognee + pgvector

What is the Second Brain?

The second brain is Jarvis's long-term memory. It remembers every meeting, every decision, every person — and can recall any of it instantly. It uses two systems that work together.

Cognee — The Mind Map

OPEN SOURCEAPACHE 2.0

Stores entities and relationships like a mind map. WHO said WHAT to WHOM, WHEN.

github.com/topoteretes/cognee

pgvector — The Search Engine

OPEN SOURCEPostgreSQL Extension

Stores text as numerical vectors. Finds relevant information by meaning, not just keywords.

github.com/pgvector/pgvector

Data stored in PostgreSQL

Both Cognee and pgvector run on PostgreSQL — the world's most trusted open-source database. One database, two superpowers.

Actual PostgreSQL Table Structure
-- Cognee Knowledge Graph tables CREATE TABLE entities ( id SERIAL PRIMARY KEY, name TEXT, -- "Bharath Kumar" type TEXT, -- "person" | "project" | "topic" first_seen TIMESTAMP, -- 2026-10-01 last_seen TIMESTAMP -- 2026-10-07 (auto-updated) ); CREATE TABLE relationships ( from_id INT REFERENCES entities(id), -- Bharath (id=1) relation TEXT, -- "attended" | "committed_to" | "discussed" to_id INT REFERENCES entities(id), -- Meeting-Oct7 (id=5) context TEXT, -- "Q4 timeline debate" source TEXT, -- "meeting-oct7-transcript" created_at TIMESTAMP ); -- pgvector Semantic Search table CREATE TABLE embeddings ( id SERIAL PRIMARY KEY, source TEXT, -- "meeting-oct7-transcript" chunk_text TEXT, -- "Bharath said APAC numbers need..." embedding VECTOR(1536), -- [0.023, -0.841, 0.112, ...] 1536 numbers metadata JSONB, -- {speaker, timestamp, meeting_id} created_at TIMESTAMP ); -- One PostgreSQL database. Two superpowers. All data in one place.

Deep Dive Voice Pipeline — STT, TTS & Costs

Speech-to-Text (STT) — FREE

APPLE BUILT-IN$0 COST

Uses Apple's on-device SFSpeechRecognizer. Runs entirely on the iPhone — no API call, no server cost, works offline for short phrases. 60+ languages supported.

Text-to-Speech (TTS) — PAID

Converts Jarvis's text response into a natural-sounding voice that plays on the iPhone speaker. This is the only voice component that costs money.

Voice Customization

We choose the voice: male or female, accent (US, UK, Indian English, etc.), speaking speed. The voice stays consistent — Jarvis always sounds the same. Can change anytime without code changes.

Cost estimate

200 voice interactions/day × ~100 chars = 20K chars/day
Monthly: ~600K chars = ~$2.40/month with Polly
Even heavy usage stays under $5/month per user.

Summary Why This Approach — Delivery in 1 Week

🔒 Is it secure?

EU data residency (Frankfurt). Encryption at rest and in transit. Per-agent least privilege — each agent can only access what it needs. Agent council verifies every external action. Full audit log. No content in logs. GDPR-ready from day one.

✓ Is it feasible?

Every component is proven open-source: LangGraph (MIT), Cognee (Apache 2.0), pgvector (free), FastAPI (MIT). We assemble battle-tested components — we do not invent new technology.

✗ Why not use Copilot?

Copilot is a chat window. Jarvis is an autonomous system.

Copilot cannot: run background agents, auto-summarize meetings, schedule follow-ups, verify actions with a multi-model council, build a private second brain, or learn the user's preferences over time. Different category entirely.
